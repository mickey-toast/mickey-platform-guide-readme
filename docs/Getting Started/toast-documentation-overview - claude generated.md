# Toast documentation overview

Toast technical documentation lives at [doc.toasttab.com](https://doc.toasttab.com). It covers the Toast platform in depth: the APIs you integrate with, the products those APIs expose, and the changes that land in each release.

This page explains how the site is organized and which section to start with.
This document was created by Claude and not intended for actual use. 

## Who the documentation is for

The documentation site opens by asking how you work with Toast technology, because the right starting point depends on your access type.

| Audience | Situation | Where to start |
| --- | --- | --- |
| Standard API access | Self-service API access purchased from the Toast Shop, for integration needs not covered by existing solutions | [Using standard API access](https://doc.toasttab.com/doc/devguide/devApiAccessUserGuide.html) |
| Analytics API access | Restaurant Management Suites Pro customers who want deeper performance insight | [Analytics API access overview](https://doc.toasttab.com/doc/devguide/apiAnalyticsAccessOverview.html) |
| Custom API access | An in-house development team building a tailored integration, with access requested through a Toast account representative | [Custom API access overview](https://doc.toasttab.com/doc/devguide/apiCustomIntegrationOverview.html) |
| Partners | External technology companies extending the Toast platform through the Toast Partner Integrations program | [Partner integration overview](https://doc.toasttab.com/doc/devguide/apiPartnerIntegrationOverview.html) |
| Platform administrators | Businesses using Toast products who need detailed product information but are not building an integration | [Platform guide](https://doc.toasttab.com/doc/platformguide/index.html) |

If you do not have a partner agreement yet, you can [apply for partnership](https://pos.toasttab.com/partners).

## The five main sections

**[How-to guides](https://doc.toasttab.com/doc/cookbook/index.html)** — Task-oriented recipes for building specific integration types. Start here when you know the business outcome you want and need the sequence of API calls that gets you there.

**[Developer guide](https://doc.toasttab.com/doc/devguide/index.html)** — Conceptual and procedural material for building and customizing integrations: REST fundamentals, authentication, access models, and API behavior. This is the connective tissue between the how-to guides and the reference.

**[API reference](https://doc.toasttab.com/openapi/)** — Generated reference for endpoints, parameters, request and response bodies, and data definitions. Use it to confirm exact field names and shapes.

**[Platform guide](https://doc.toasttab.com/doc/platformguide/index.html)** — In-depth technical detail about Toast platform products and features, independent of the API. Useful for administrators and for developers who need to understand what a feature actually does before integrating with it.

**[Release notes](https://doc.toasttab.com/doc/relnotes/index.html)** — Platform and API changes over time.

## A typical path for a new integrator

1. Confirm which access type applies to you, using the table above.
2. Read [the basics of building API integrations](https://doc.toasttab.com/doc/devguide/apiUsingRestApis.html).
3. Set up [authentication](https://doc.toasttab.com/doc/devguide/authentication.html).
4. Review [the available endpoints](https://doc.toasttab.com/doc/devguide/apiOverview.html).
5. Follow the [how-to guide](https://doc.toasttab.com/doc/cookbook/index.html) that matches your use case.
6. Subscribe to [API change notifications](https://doc.toasttab.com/doc/devguide/apiUpdatesEmailDistributionList.html).
